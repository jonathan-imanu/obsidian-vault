Software engineering is the application of scientific principles to the design and
creation of software
### SDLC Phases

1. Planning - requirement gathering and development of the SRS.
2. Design - The architecture is developed during the design phase and the design document is created.
3. Development - Coding takes place
4. Testing - Issues with the code are found and fixed if possible.
5. Deployment - Releasing the code to the production environment.
6. Maintenance - Feedback is collected from stakeholders, other UI issues may be identified, and code enhancements suggested.
## Different Software Development Models
### Agile Software Development 

A project management approach that seeks to respond to change and unpredictability, primarily using incremental, iterative work sequences called sprints.

- A set of software engineering best practices ( allowing for rapid delivery of high quality software)
- A business approach (alignment of business / client needs with goals)
#### Scrum Elements

##### Product

- Product Backlog: All the features of the product
- Sprint Backlog: All the features that will be worked on for that sprint. This is broken down into the following tasks:
	- Refined
	- Estimated
	- Assigned to individual
	- Clear acceptance criteria
##### Process

- Sprint planning backlog meeting
	- Entire team decides together what to tackle for this sprint
- Daily scrum meeting 
- Sprint Retros
	- Review sprint progress
- Sprint Review meeting
	- Review product
##### Collective Ownership

Any developed can change anything. **No single person can become a bottleneck for changes.**
#### Burndown Charts

A project management chart that shows how quickly a team works through client user stories.

There are two main variants:
1. Sprint Burndown: Used for work remaining in the iteration
2. Product Burndown: Used for work remaining in the product

X-axis: Time
Y-axis: User story points remaining
### Extreme Programming

An iterative incremental model that emphasizes on technical aspects of software development. The customer's decision drives the project.
### Test Driven Development

- Programmers write a failing unit test case for the simplest piece of functionality that you need to implement
- Refactor the code to pass or meet the standards of the code
## Pair Programming Styles

- Driver / Navigator
	- "Driver" types the code
	- "Navigator" reviews the code as written
- Ping - Pong
	- First developer writes a test 
	- Second developer writes a code to pass the test
-  Strong Style 
	- Pair a junior programmer with senior one 
	- Senior programmer is navigator 
	- Junior programmer is driver
