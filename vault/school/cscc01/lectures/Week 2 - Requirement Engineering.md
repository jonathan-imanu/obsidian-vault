Requirement Engineering is the fist step in building software. It's challenging, costly and potentially risky.

Requirements are essential to ascertain a definition of done for developers and testers as well as to provide clarity to customers so that they know what to expect.
## User Story

A small unit of work that's told from the perspective of a user. A crucial part of the Agile process that explains desired functionality.
- *This differs from a traditional requirement written from the perspective*
- Should have **acceptance criteria** that sets the scope and helps to validate whether the story is complete or not. Ideally this should be automated.
### User Personas

Helps to visualize the kind of person that might be using the product.
## React

A JS library for building UI. 
- Mostly JS and JSX (a syntax extension for JS).
- JSX let's you write HTML code in JS files
- React follows a component based architecture and has one way data flow. 
### DOM

A JS object that contains all the elements you have in your HTML. This allows JS to find, add and update elements without reloading the page.

React introduces the concept of a Virtual DOM. React applies changes to the Virtual DOM and computes diffs of the Virtual DOM to the DOM and updates the DOM accordingly.
### Component State & Lifecycle

- A special JS object that can store data inside of a component
- **Hooks** a way to hook into the component lifecycle
	- `useState` a hook that lets us persist data across re-renders and force a re-render when there is a change in state.
	- `useRef` is a React Hook that lets you reference a value that's not needed for rendering
