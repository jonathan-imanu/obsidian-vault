**Very Simple File System (vsfs)**: This file system is a simplified version of a typical UNIX file system and  

Two main aspects:
1. **Data structures** employed by the file system
2. **Access Methods**: How the FS maps process calls onto it's data structures
## Organization

Divide the disk into fixed-size **blocks**
- **Data Region**: The region of the disk that's used for the user data in a filesystem.
	- The majority of blocks are a part of the data region
- **Metadata**: Information about each file such as it's size, owner and access rights. *This information is stored in a data structure called inodes*.
	- Some disk space must be used for inodes. The portion of the disk that holds these is called the **inode table**.
- **Allocation Structures**: A way to track whether inodes or data blocks are free or allocated.
	- *Free list* that points to the first free block which then points to the next block and so on.
	- **Bitmap**: A structure where in which each bit is used to indicate whether the corresponding object/block is free or in-use. 
		- A file system has two: **Data Bitmap** & **Inode Bitmap**
- **Superblock**: Contains information about this particular file system
## Inode

Short for index node.

Each node is referred to by a number (called the **i-number**). Given an i-number, we can directly calculate where one disk the inode is located.

A inode has all of information needed for a file: type, size, number of blocks allocated to it, protection information (who owns the file and who can access it), time information, where data blocks reside on disk.
- All of these are referred to as metadata. 
### Multi-Level Index

We can't just use **direct pointers** (disk addresses) inside the inode because we can't handle files that are larger than the block size multiplied by the number of direct pointers in the inode.

**Indirect Pointers**: Points to a block that contains pointers, each of which points to user data.

> Suppose we have 12 direct pointers, 1 indirect pointer, 4-KiB blocks and 4-byte disk addresses. What's the largest file an inode can store? 

We have 1024 additional pointers (4096 / 4) as the indirect pointer points to a block of direct pointers. 

So the file can grow to be $(12 + 1024) · 4K = 4144KB$ 

To store a larger file, add a **double indirect pointer** or even **triple indirect pointer**

*This design works well because most files are small.*
## Directory Organization

A directory contains a list of (entry name, inode number) pairs. For each file or directory, in a given directory, there is a string and a number in the data block(s) of the directory. 

![[Directory Example.png]]
- A directory `dir` (inode number 5) with three files. 
- `reclen` is the size of the name and any leftover space.
- `strlen` the actual length of the name
- Each directory has two extra entries representing current and parent directory

Deleting a file can leave an empty space in the middle and we can mark this with a reserved inode number such as zero. 
## Access Paths: Reading and Writing

### Reading

Given `open("/foo/bar", O_RDONLY)` syscall:
- Find inode for the file bar by traversing the pathname
	- Start at root directory `/`
		- The inode number for this directory must be well-known and it is 2 on Unix.
	- Read in the block corresponding to inode 2
	- Use the pointers to find an entry for `foo`
	- Repeat this pattern until `bar` is found
- OS performs a permissions check, allocates an FD for this process in the per-process open-file table and returns it to the user

A following `read` call will consult the inode table to find the first block of the file and will update the in-memory open file table.
### Writing
 Similar to reading, except this operation may allocate a block.
## Caching and Buffering

Reading and writing files incurs many I/Os to the (slow) disk.

Most file systems aggressively use system memory (DRAM) to cache important blocks.
- Early file systems would allocate a **fixed-size cache** like **LRU** and allocate it at boot time to be roughly 10% of total memory. This **static partitioning** of memory can be wasteful. 
- Modern systems employ a dynamic partitioning approach where they integrate virtual memory pages and file system pages into a **unified page cache**.

Read I/O can be completely avoided if the cache is big enough but writes must go to disk to be persistent. 

### Write Buffering

Delaying writes so that the FS can batch some updates into a smaller set of I/Os and schedule the subsequent I/Os in a manner that increases performance.
