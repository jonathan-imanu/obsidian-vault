## Autonomous Systems

The internet is divided into **autonomous systems** (routing domains) each of which is under the
control of (and corresponds to) a single administrative entity (University, company, backbone network etc.). 
- Neighbouring systems will interact to coordinate routing and have business relationships.
- They can be identified by 32 bit values called **AS Numbers**

**Inter-domain Routing**: A network with routing between two autonomous systems.
### AS Topology

- **Node:** Autonomous System
	- There is a high variability in node degree ("power law") as there are only a few very highly-connected AS's while most only have a few connections
- **Edge:** Two AS’s that connect to each other

AS topology can be inferred by:
- Mapping `traceroute` data to the AS level
- Measurements of the inter-domain routing protocol

These approaches are hard because data is often out of date and data collection is also difficult.
- Seeing peer-peer edges is difficult.

![[GlobalInternet.png]]
#### Business Relations within AS'

##### Customer Provider

- Customer needs to be reachable from everyone 
	- The job of the provider
- Customer does not want to provide a transit service
	- Traffic in but no traffic out (unless it originates from the customer)
##### Peer-Peer Relationship

Peers exchange traffic between customers.
- AS exports only customer routes to a peer
- AS exports a peer’s routes only to its customers

You will never see a path taking two peer edges because an AS will only share customers with a peer. *It will not carry traffic between two non-paying systems for free.*

**Backbone networks** Have multiple Points-of-Presence (PoPs) with lots of communication between PoPs. They accommodate traffic demands and limit delay.
- *Inter-PoP links* are long distance and high-bandwidth
- *Intra-PoP links* are shorter cables that have aggregated bandwidth

**Multi-Homing**: Having two or more provider. Benefits include:
- Extra reliability can survive a single ISP failure
- Gain financial leverage through competition
- Better performance by selecting the better routing path
### AS Classification

**Local Traffic**: Traffic that terminates on nodes within an AS
**Transit Traffic**: Traffic that passes through an AS

Using the above, AS can be classified into:
- **Stub AS**: An AS that has only a single connection to one other AS; such an AS will only carry local traffic (small corporation).
- **Multihomed AS**: An AS that has connections to more than one other AS but refuses to carry transit traffic (large corporation).
- **Transit AS:** an AS that has connections to more than one other AS and is designed to carry both transit and local traffic (backbone providers).
# Route Propagation

Provide an additional way to hierarchically aggregate routing information is a large internet. Divide the routing problem in two parts:
1. Routing within a single autonomous system (selected by an AS)
2. Routing between autonomous systems (an internet-wide standard)
## Interior Routing Protocols

#### RIP

An older algorithm originally used in BSD UNIX. Had no auth and uses distance vector (distributed Bellman-Ford algorithm) with updates sent every 30 seconds.

#### OSPF

Widely used algorithm that partitions AS into areas. Uses Dijkstra's algorithm with link-state updates sent (using flooding) when required. Updates are authenticated.
## Inter-domain Routing Protocols

### Exterior Gateway Protocol (EGP)

- Forced a tree-like topology onto the Internet: a single backbone with ASs connected as parents and children rather than peers.
- BGP instead supports an arbitrarily interconnected set of ASs.
### Challenges with Inter-domain Routing

1. **Scale:** Routers must store routes for many destination prefixes and process updates when routes change.
2. **Privacy:** ASs do not want to reveal internal topologies or business relationships.
3. **Policy:** There is no Internet-wide definition of the best route or shared link-cost metric. Each AS controls where it sends traffic and whose traffic it carries.
4. **Trust:** An AS may not trust another AS’s advertisements.

**Link-state routing is problematic between ASs** because flooding topology information creates bandwidth, storage and processing overhead, reveals sensitive information, and assumes a shared routing objective.

**Distance-vector routing** hides internal topology, but relies on distance metrics and can suffer from count-to-infinity. Path-vector routing extends this approach by advertising paths rather than just distances.
### Border Gateway Protocol (BGP)

BGP is a **prefix-based path-vector routing protocol** that supports an arbitrarily interconnected Internet.

**Goal:** Find a loop-free, policy-acceptable path to the destination. Reachability is more important than globally optimal routing.
- A **BGP speaker** advertises local prefixes and other reachable prefixes permitted by its export policy.
- **Border gateways** are routers through which packets enter and leave the AS. They need not be the same routers as the BGP speakers.
- An AS can contain multiple BGP speakers and border gateways.

It is **slow** because *BGP may try several loop-free alternatives before discovering they are also unavailable, causing slow convergence.*
#### Path-vector Routing

**BGP announcement = destination prefix + path attributes**

An important attribute is `AS_PATH`, the sequence of ASs through which a prefix can be reached.
- Lists ASs, not individual routers.
- When advertising a route externally using eBGP, an AS prepends its own AS number.
- A receiving AS rejects a path containing its own AS number to prevent an AS-level loop.
- AS numbers must be unique for this loop detection to work.
- Advertisements propagate outward from the destination; packets following the advertised route travel toward the destination.

Example: AS 30 originates `203.0.113.0/24`.

|Advertisement|AS_PATH|
|---|---|
|AS 30 → AS 20|`30`|
|AS 20 → AS 10|`20 30`|
|AS 10 → AS 40|`10 20 30`|
AS 40 can send packets along `40 → 10 → 20 → 30`.

AS 20 would reject a received advertisement containing `10 20 30` because its own number appears in the path.
#### BGP Sessions and Messages

BGP runs over **TCP port 179**.

1. Establish a BGP session.
2. Exchange active routes.
3. Send **incremental updates** when routes change, rather than repeatedly sending the entire routing table.

|Message|Purpose|
|---|---|
|**OPEN**|Establish a BGP session|
|**KEEPALIVE**|Maintain the session and help detect an unresponsive peer|
|**NOTIFICATION**|Report an error and shut down the session|
|**UPDATE**|Announce routes or withdraw previously announced routes|

A router may learn several candidate routes, select an active route using local policy, and advertise it to eligible neighbors.

- **Announcement:** Advertise a new or changed route.
- **Withdrawal:** Remove a previously advertised route. A receiver may then select an alternative.
- **Session failure:** Discard routes learned from that neighbor and update affected advertisements.
#### Route Attributes and Selection

|Attribute|Purpose|
|---|---|
|**NEXT_HOP**|IP address toward which packets for the prefix should be forwarded|
|**AS_PATH**|Sequence of ASs used for loop detection and route selection|
|**LOCAL_PREF**|Preference within an AS; higher values are preferred|
|**MED**|Multi-exit discriminator; lower values are preferred when applicable, influencing the entry point into a neighboring AS|

A common business preference is:

**Customer route > peer route > provider route**

Operators express this preference using **LOCAL_PREF**. 

![[BGPPrefs.png]]

**Fewer AS hops does not necessarily mean fewer router hops or lower delay.**
#### Import and Export Policies

**Import policy:** Controls which received routes are accepted and how they are ranked.

- Filter unwanted or suspicious advertisements.
- For example, reject a customer’s announcement of a prefix it does not own.
- Modify attributes such as LOCAL_PREF to influence route selection.

**Export policy:** Controls which routes are advertised to each neighbor and which attributes are sent.

- Avoid advertising routes learned from one peer to another peer.
- Filter routes for private network-management hosts.
- Modify attributes to influence other ASs’ decisions.

**AS-path prepending:** Repeat your own AS number in an advertisement to make the path appear longer. This may encourage other ASs to choose another route, but their local preferences can override path length.

Typical export rules, in addition to advertising your own prefixes:

|Route learned from|To customers|To peers|To providers|
|---|---|---|---|
|Customer|Yes|Yes|Yes|
|Peer|Yes|No|No|
|Provider|Yes|No|No|

These policies avoid providing unpaid transit between peers or providers.

They produce **valley-free paths** (provider -> customer -> provider):

1. Zero or more customer-to-provider links.
2. At most one peer link.
3. Zero or more provider-to-customer links.
#### Integrating Inter-domain and Intra-domain Routing

![[BGP_IGP.png]]

An AS contains multiple routers, so external route information must also be distributed internally

|Component|Role|
|---|---|
|**eBGP**|Exchange BGP routes between different ASs|
|**iBGP**|Distribute BGP routes between routers within the same AS|
|**IGP**, such as OSPF|Compute paths through the internal network, including paths toward BGP next hops|

**iBGP does not replace the IGP.**

- BGP identifies external reachability and the next hop toward a destination.
- The IGP determines how to reach that next hop through the AS.
- Sharing a route through iBGP does not prepend the AS number at every internal router.

Example at an internal router:

1. **BGP:** `128.112.0.0/16` is reachable through next hop `192.0.2.1`.
2. **IGP:** Reach `192.0.2.1` through adjacent router `10.10.10.10`.
3. **Combined forwarding entry:** Send packets for `128.112.0.0/16` to `10.10.10.10`.

A BGP advertisement alone is insufficient if its next hop cannot be reached.
#### Convergence and Path Exploration

**Path-vector routing avoids count-to-infinity, but BGP can still converge slowly or fail to converge.**

After a failure, routers may successively select and advertise alternative paths before discovering that those paths are also unavailable. This is **path exploration**.

Routing changes can result from:
- Equipment or link failures.
- BGP session failures.
- Deployment of new routers or sessions.
- Changes to routing preferences or filters.
- Conflicting policies that cause persistent oscillation.

Convergence can take **tens of seconds to tens of minutes**. Most popular destinations generally have stable routes.
# IPv6

A classless addressing / routing system (CIDR-like) with 128-bit addresses. Major features include:
• Multicast
• Real-time service
• Authentication and security
• Auto-configuration
• End-to-end fragmentation
• Enhanced routing functionality, including support for mobile hosts

Notation: `x:x:x:x:x:x:x:x (x = 16-bit hex number)`
- You can replace a consecutive sequence of all-zero groups with `::`. Use `::` **only once per address**, so expansion is unambiguous.
### Header Structure

There is a 40-byte base header with extension headers as well as source and dest address.

With **end-to-end fragmentation**, the source performs fragmentation and the destination reassembles the packet; intermediate routers do not fragment it.
# Internet Multicast

Internet multicast means sending packets to a group of receivers, instead of sending a separate copy to each receiver.
- Receivers join a multicast group, identified by a multicast IP address. Routers copy packets where paths split, so shared links carry only one copy.

**A multicast group** will have it's own IP address that the sender will need. It does not need the address of each member within the group. 

A host signals its desire to join or leave a multicast group by communicating
with its local router using a special protocol
-  In IPv4, the protocol is *Internet Group Management Protocol (IGMP)*
- In IPv6, the protocol is *Multicast Listener Discovery (MLD)*
#### Models of Multicast

##### One-to-many Multicast -- Source Specific Multicast (SSM)

A receiving host specifies both a multicast group and a specific sending host.
##### Many-to-many Multicast: Any Source Multicast (ASM)

## Multicast Routing

Unicast forwarding selects one outgoing interface toward a destination. Multicast forwarding can select **multiple outgoing interfaces**, collectively forming a **distribution tree**.

```text
                         R2 ─── Receiver A
                        /
Source S ─── R1 ─────── R3 ─── Receiver B
                        \
                         R4 ─── Receiver C
```

For each original packet:

- S sends one copy to R1.
- R1 sends one copy along each necessary branch.
- The shared link between S and R1 carries only one copy.

Multicast forwarding state identifies:

- The expected incoming interface.
- The outgoing interfaces on which copies should be sent.

For SSM, forwarding depends on both the source and group, `(S, G)`.
## Reverse-Path Forwarding (RPF)

Blindly forwarding packets on every link can create loops and duplicates.

**RPF checks whether a multicast packet arrived on the interface the router would use to reach the source.** The check uses the route toward the source, not toward the receivers.
### Distance-Vector Multicast

Distance-vector multicast uses routing information toward the source to construct a source-rooted delivery structure.

- Accept a packet only from the expected upstream neighbor.
- Forward onto eligible outgoing links, excluding the incoming link.
- On a shared LAN, select a designated parent router to avoid duplicate forwarding.
- Parent selection uses distance toward the source, with an address-based tie-break when needed.
## Pruning

**Pruning removes branches that have no receivers for a multicast group.**

In a flood-and-prune approach:

1. Packets initially spread through the forwarding structure.
2. A leaf router checks whether its local network has group members or if receivers exist farther downstream.
3. If it has no local members and no downstream branches requiring traffic, it sends a prune upstream.
4. Its upstream router stops forwarding that group’s traffic onto the branch.
5. Pruning can propagate farther upstream as entire branches become unnecessary.

## Protocol Independent Multicast (PIM)

PIM uses existing unicast routing information without requiring a particular unicast routing protocol.

### Shared Tree and Rendezvous Point

In **PIM Sparse Mode (PIM-SM)**, a **rendezvous point (RP)** acts as a meeting point for sources and receivers.

1. Receiver-side routers send **Join messages toward the RP**.
2. These joins build a shared distribution tree.
3. A source-side router initially tunnels the source’s packets to the RP.
4. The RP forwards packets down the shared tree.
5. The RP can join a source-specific tree toward the source.
6. Receiver-side routers may also switch to source-specific trees to obtain more direct delivery.
### Shared vs Source-Specific Trees

|Tree|Root|Main tradeoff|
|---|---|---|
|**Shared tree**|Rendezvous point|Multiple sources share a tree, but delivery may take a detour|
|**Source-specific tree**|Particular source|Provides source-rooted paths, but requires state for individual sources|

Switching to a source-specific tree avoids routing that source’s traffic through the RP.

# Mobile IP

An IP address normally identifies a network location. If the device moves but keeps its address, ordinary routing still sends its packets toward its **home network**. The solution to provide a permanent IP address but still allow mobile devices is mobile IP.

![[MobileIP.png]]

### Triangle Problem

A UTSC student is in Toyko connected to a University WiFi network. The are receiving packets from a computer also in Toyko. Without route optimization:

`Tokyo sender → Toronto home agent → tunnel back to Tokyo → student laptop`

**Care-of-address**: An IP address that tells the network where to deliver packets for a mobile device while it is away from its home network.

To avoid the triangle problem:
1. Tell the sender the care of address
2. Home agent sends a binding update message to the sender
	1. This tells the sender that the mobile device at this home address is currently reachable at this care-of-address
3. The sender creates an entry in the binding cache
4. The previous foreign agent sends a binding warning message to the home agent if the mobile node moves to a different network / foreign agent

## Cloud Systems

Cloud providers operate datacenters in many locations, often near **Internet Exchange Points (IXPs)** which are places where networks interconnect.

- **Distribute popular content near users.** Serving content from a nearby location reduces the distance traffic must travel and can reduce delay.
- **Connect datacenters through private backbones.** Providers use their own networks to move data between locations and keep distributed content synchronized.

## MPLS: Multi-protocol Label Switching

A hybrid of virtual circuits and datagrams. It brings two main capabilities to IP:
1. **Traffic engineering:** Steer traffic onto selected paths, such as less congested alternatives.
2. **VPNs:** Connect an organization’s sites with private routing and addressing over a shared provider network.
