## Link Capacity and Shannon-Hartley Theorem

Gives the upper bound to the capacity of a link in terms of bps as a function of signal-to-noise ratio of the linked (measured in decibels).

$C = B \log_{2} (1+ \frac{S}{N})$ where
- $B$ is bandwidth
- $S$ is the average signal power and $N$ is the average noise power
	- $dB = 10 \times log_{10}(S / N)$
## Encoding

#### Definitions

**Baud Rate**: The rate at which the signal changes within a link
**Encoding**: Placing binary data on a signal.
**Modulation**: Involves modifying the signals in terms of their frequency, amplitude and phase.
## Problem

**Problem**: We need to transmit bits over a physical media by continuous physical signals.

General problems that come with encoding solutions:
1. **Clock Recovery**: Both sender and receiver operate with internal clocks. If sender transmits 1000 zeros in a row, the receivers clock will drift and lose track of how many zeros were transmitted.
	1. Frequent transition from high to low or vice versa are necessary to enable clock recovery
2. **Baseline Wander**: The receiver determines whether a signal is `0` or `1` by comparing the incoming voltage against a baseline (ongoing average). 
	1. Too many consecutive `1`s or `0`s make this average to change and difficult to detect
### NRZ: Non-Return to Zero

A high signal level corresponds to a `1` and low signal level corresponds to a `0`.  Although simple and intuitive, it suffers from clock recovery and baseline wander issues
### NRZI: Non-Return to Zero Inverted

A **differential** encoding where the sender makes a transition from the current signal to encode `1` and stays at the current signal to encode `0`.
- **Pro**: Fixes clock recovery / drift and baseline wander for consecutive `1`s
- **Con**: Still has baseline wander and clock recovery issues for consecutive `0`s
### Manchester Encoding

$$\text{Signal} = \text{NRZ Data} \oplus \text{Clock}$$
- `0` corresponds to a low-to-high transition in the middle of the bit interval
- `1` corresponds to a high-to-low transition in the middle of the bit interval

**Problems**:

- Doubles the rate at which signal transitions are made on the link
	- The receiver has half of the time to detect each pulse of the signal

In Manchester, **the bit rate is half the baud rate.**
### 4B/5B Encoding

Insert extra bits into the bit stream to break up the long sequence of `0`s and `1`s.
- Every 4-bits of actual data are encoded in a 5-bit code that is transmitted to the receiver.
- 5-bit codes are selected in such a way that each one has no more than one leading 0(zero) and no more than two trailing 0’s.

# Error Detection

Give some number of redundant bits to frame that we can use to determine if errors have been introduced. We will have $k$ redundant bits with a $n$ bits message where $k <<< n$.
## The Hamming Distance

Errors must not turn one valid codeword into another valid codeword or we cannot detect/correct them.

**Hamming distance** of a code is the smallest number of bit different that turn any one codeword into another.
- Eg. Hamming distance of `000` to `111` is 3
- For a code with distance $d + 1$, we can detect $d$ errors

To reliably detect a d-bit error: $HD \geq d + 1$
TO reliably correct a d-bit error: $HD \geq 2d + 1$

The number of redundant bits is determined by $2^r \geq m + r + 1$ where $m$ is data bits and $r$ is the redundant bits.
- Each redundant bit is placed at a power of 2 and covers all bits where the bitwise `AND` of the parity position and the bit position is non-zero. Set parity bit to 1 if the number of 1s in the positions it checks are odd.
## Error Detection

Extra bits are redundant and add no new information to the message. They are derived from the original message using an algorithm that both the sender and the receiver know.
### Two-Dimensional Parity

For each byte, we add a parity bit such that the byte has even parity. We then form a parity block by adding parity bits for each column. If a single bit flips, its row and column will both have incorrect parity, allowing us to identify the exact location of the error and correct it.

It can detect 1-4 bit errors but only reliably fix 1 bit errors.
## Internet Checksum Algorithm

Not used at the link level.

Add up all the words that are transmitted and then transmit the result of that sum (the **checksum**).
### How it works

Suppose the data being checksummed is a sequence of 16-bit integers.
- Add them together using the ones complement notation. Any carrys should be added back to the end.
## Cyclic Redundancy Check (CRC)

Reduce the number of extra bits and maximize protection.
- Given a bit string $s$ we can associate a polynomial on a single variable `x` for it
	- A $k$-bit frame has a maximum degree of $k - 1$

Let $M(x)$ be a message polynomial and $C(x)$ be a generator polynomial.

 CRC is used to detect errors . Some error codes are strong enough to correct errors.
- The overhead is typically too high and corrupt frames must be discarded.
- A link-level protocol that wants to deliver frames reliably must recover from these discarded frames

### Process

Given a message $m$ and a generator polynomial $C(x)$. 

**The sender**:
1. Adds $degree(C(x)) = \text{generator bit length}-1$ 0 bits we will add to $m$. 
2. Performs XOR long-division with the generator and message and then replaces the zeros with the remainder. 
	1. It is these extra bits that are used for protection. 

When **the receiver** receives the transmitted frame $r$, it performs XOR long division on $r$ using the same generator polynomial $C(x)$.
- Nonzero remainder: An error has definitely been detected.
- Zero remainder: No error was detected, although an error may still have occurred.
## Reliable Transmission

An acknowledgement (ACK for short) is a small control frame that a protocol sends back to its peer saying that it has received the earlier frame
- A control frame is a frame with header only (no data)
- The receipt of an acknowledgement indicates to the sender of the original frame that its frame was successfully delivered.

If the sender does not receive an acknowledgment after a reasonable amount of time (timeout), then it retransmits the original frame.

**Automatic Repeat reQuest (ARQ)**: Describes the general strategy of using ACKs and timeouts to implement reliable delivery.

### Stop and Wait Protocol

Transmit one frame and wait to receive an ACK from receiver before transmitting the next frame. If an acknowledge is not received before the timeout, retransmit the original frame.
- If an ACK is delayed, the sender will retransmit the original frame. To ensure that the sender is able to recognize that this is a duplicate, we use a 1 bit sequence number.
