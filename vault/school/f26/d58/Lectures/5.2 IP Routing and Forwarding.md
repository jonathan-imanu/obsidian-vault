#### **Forwarding vs Routing**

**Forwarding**: Selecting an output port based on destination address and routing table. A data-plane action.
- A *forwarding table* is used when a packet is being forwarded. A row contains the mapping from a network number to an outgoing interface and some MAC information, such as Ethernet Address of the next hop.
**Routing**: The process by which a routing table is built. This is computing paths the packets will follow. A control-plane action.
- *Routing table* used by the routing algorithm as a *precursor* to build the forwarding table. A mapping of network number to next hop.

**Hop-by-Hop Packet Forwarding**: 

Router receives a packet. It then:
1. Inspects destination IP address
2. Indexes into the table
3. Determines the outgoing interface
4. Forwards the packet out that interface
# Routing Algorithms

Problem can be viewed as finding the lowest cost path between any two nodes. But this is much harder than a basic graph problem because networks are not static:
- Node or links can fail
- New nodes or links can be added
- The cost of an edge can change
## Naive Flooding

Routers forward packets to all ports except the ingress port. Although simple, it is inefficient as routers can receive the same packet multiple times and loops are possible.
## Distance Vector (Bellman-Ford)

*An iterative, asynchronous and distributed version of Bellman-Ford.*

Each node constructs a 1D array containing the "distances" to all other nodes and distributes that vector to its immediate neighbours.
- Assumes that a node knows the cost of the link to each of its directly connected neighbours

Every $T$ seconds each router sends its table to its neighbour, each router then updates its table based on the new information.

When a node detects a link failure, it will set the distance to $\infty$ and send an update to it's neighbours.
### Count to Infinity Problem

Under the wrong sequence of table updates, we could run into the **count-to-infinity** problem. A cycle where the distance to reach a node after a link failures keeps increasing up until $\infty$ that will only be detected once an abnormally high number is reached.
- We can use some relatively small number as an approximation of infinity.

**Split-Horizon**: Don't send include the routes learned from a neighbour in table updates.
- **Split-Horizon with Poison Reverse**: When negative information (setting count to infinity) is included in the table updates for rows where the route was learned from a neighbour. Done to ensure that the neighbour will never use the information it provided to derive it's own path.

## Link State Routing 

Send to all nodes information about directly connected links using **Link State Packets (LSP)**.
- LSPs contain the id of the node and the cost each link to directly connected neighbours of said node. They include a sequence number and a TTL.

We can use LSPs to do reliable flooding because we can discard packets when $TTL = 0$ and use the $SEQNO$ to differentiate link updates.

Use Dijkstra's algorithm where the graph is formed from all the LSPs a node has received so far.
- Maintains two lists tentative and confirmed but tentative can essentially viewed as the heap within Dijkstras
