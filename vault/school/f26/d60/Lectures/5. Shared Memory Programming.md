**Idea**: A singular blob of memory with multiple cores acting on it. Coordination is done through memory rather than by messages.

**Shared Memory Languages**:
- **pthreads**: POSIX threads, heavyweight, lower level and more clumsy
- **PGAS languages**: Partition Global Address Space UPC, Titanium, Co-Array Fortran
- **OPenMP**: An API shared memory parallel programming
#### UMA vs NUMA

**Uniform Memory Access**: A core can access any part of memory (RAM) with the same latency.
**Non-Uniform Memory Access**: A core can access its local RAM faster than it can access RAM attached to another group of cores.

# OpenMP

An API for multi-threaded, shared memory parallelism. OpenMP is designed for multi-processor/core, shared memory machines. The underlying architecture can be shared memory UMA or NUMA

A set of compiler directives inserted in the source program.
- Pragmas in C/C++
- Env. var. `OMP_NUM_THREADS` determines how many threads will be started in an OpenMP parallel block.

## Memory Model

All threads access the same, globally shared memory
- Data can be shared or private
- Shared can only one instance of data

OpenMP has relaxed-consistency shared memory model:
- Threads may have a temporary view of shared memory that is not consistent with that of other threads
- These temporary views are made consistent at certain places in code
## Constructs

Constructs (compiler directives) in OpenMP apply to a structured block.
- **Structured block:** A block of one or more statements with one point of entry at the top and one point of exit at the bottom

- `pragma omp parallel` - use OpenMP within a structured block
- `shared(variable)`: Give each thread read/write access to `variable`. Convenient for reading but introduces potential race conditions for assigning values.
- `private(variable)`: Separate instance of `variable` for each thread. Thread-private versions do not have the value of the variable outside the parallel loop. They cease to exist after the parallel region.
- `default(none)`: If a variable within a structured block is not classified with `shared` or `private` the compiler usually decides UNLESS this directive exists where compilation will fail.
- `single(variable)`: First thread that gets it, gets it. 

Use `#pragma omp for` on a `for` loop to do worksharing.

To avoid race conditions in critical regions of the code, use the `critical` construct to allow only one thread to be operating within that region at a time.
- This can be super slow!

**What about atomic instructions?**

Most hardware has support for this: `#pragma omp atomic [read|write|update|capture]`
### Reductions

Taking a bunch of data and summing it to one value: **reduction**. OpenMP supports this with **reduction variables**.

When declaring a variables as reduction variables, private copies are made (much as for private variables), which are combined at the end of a parallel region through some operation (+, *, min, max).
- `reduction(+:tot)`
### Load Balancing

`omp for` tries its best to subdivide an iteration to equal consecutive chunks among the threads but this may not always be the best approach as threads may sit idly by.  

Alternatives:
- `#pragma omp parallel for schedule(static, m)` gives `m` consecutive loop elements to each thread instead of a big chunk using a round robin approach
- `schedule(dynamic, m)`: each thread will work through m loop elements, then go to the OpenMP run-time system and ask for more
	- Load balancing (possibly) better with dynamic, but larger overhead than with static.
