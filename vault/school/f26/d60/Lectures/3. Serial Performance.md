## Memory Hierarchy

![[MemHierarchy.png]]
- Different storage devices with different trade-offs between speed and size.

Performance suffers if:
- data needed is not close to the CPU 
- data used more than once is transferred more than once
- access of data involves multiple transactions
### Components

- **CPU Registers**: Very fast pieces of memory close to, or part of, the CPU. It’s the compiler’s job to use the small number of registers optimally, and to insert the appropriate loads and stores.
- **Cache Memory**: Intermediate memory for data currently in use by the CPU. Access is in order of few - dozen nanoseconds. Data is automatically copied into and out of cache from RAM or SSD / HDD.
	- Not under the direct control of the programmer.
- **RAM**: Main memory and slowest non-persistent storage. Access can be as slow as 100 ns. 
#### Non-Volatile Memory Types

##### SSDs (Flash)

Have access times on the order of 1 ms. 
##### HHDs

Spinning disk hard drives have access times in the order of several milliseconds.
##### Tape

Super cheap but incredibly slow access times. Reading tape is on the order of 10s or faster.
## Cache

A cache line is a number (usually 64) of contiguous bytes in memory. 
- Cache is used by copying a cacheline at time when data is needed.
- On cache miss, the cache will copy a cacheline at the time data is needed

*Cache line memory address are aligned.*

Typically, when the cache is full, it will release the oldest cacheline.

**The structure of the cache means that it is important to try and make subsequent operations access memory in a contiguous manner.**
### Cache Thrashing

When accessing memory out of order, performance becomes much worse. Each access can be a new cache line (cache miss) and result in a slow access to main memory. 
- *In a row-major language like C, cache-friendly order is to make the last index most quickly varying*
# Vectorization

A special case of automatic parallelization.  

A set of instructions in a program are converted from a scalar implementation, which processes a single pair of operands at a time, to a vector implementation, which processes one operation on multiple pairs of operands at once.
- **SIMD/SPMD:** Single Instruction/Program Multiple Data

### Automatic Vectorization Techniques

Compilers will modify and reshuffle your code in order to optimize it. 

1. Compiler’s optimizer must first understand the dependencies between statements and re-align them, if necessary
2. The optimizer must properly arrange the implementing instructions changing appropriate candidates to vector instructions, which operate on multiple data items.
	- Build the Dependency Graph
		- Which statements depend on other statements
		- **Clustering**: Using the graph, the optimizer can then cluster the strongly connected components (SCC) and separate vectorizable statements from the rest

The number of elements in a vector register within a CPU is:

$$ \text{number of elements} = \frac{\text{register width in bits}}{\text{element width in bits}}$$

#### Loop-Vectorization

Transforms a seres of instructions so that the same operation is performed at the same time on several of the elements of the vectors.
- When vectorizing a loop with several statements the compiler needs to strip-mine the loop and then apply loop distribution
- *Stripmining* is a simple transformation employed by the compiler to help with data locality.

Loops with conditional instructions need a `#pragma`
