A combination of techniques employed to optimize and take advantage of modern computer hardware.

There is no unique way to measure perf. We use **FLOPS** (Floating-point Operations per Second).

The theoretical performance of a supercomputer cluster given the clock speed s, number of cores per node c, number of nodes per rack n, total number of racks r and adjusting factor for performance p is:
$$s \times c \times n \times r \times p$$ 

HPC is needed because there is a limit to speed and size that a singular computer / machine can accomplish. Another big motivation is that hardware isn't getting much faster (unlike in the early days of computing).

**Threads**: Units of execution within a singular process. They share the same memory and resources.
**Processes**: An instance of a running program. Different processes are independent of each other and have their own memory and resources.

### Dennard's Law 
As transistors shrink, their power density remains approximately constant. 

**Dennard scaling:** Under ideal scaling, shrinking transistor dimensions and supply voltage together reduces power per transistor in proportion to transistor area. A fixed-area chip can therefore fit more transistors while keeping its total power and power density roughly constant. In practice, voltage stopped scaling proportionally, so shrinking transistors no longer guarantees constant power density.

- Total power scales with area. So given scaling factor $s$, $P_{new} = P_{old}s^2$
- $\Delta T = R_{\theta}(P_{\text{new}}-P_0)$
## Supercomputer Architectures

**Clusters**: A bunch of desktops linked together by a network.
**Multi-core machines**: A collection of processors that can see and use the same memory. Limited number of cores and much more expensive when the machine is large. 
- *Accelerator machines*, are machines that contain an "off-host" accelerator that is used for computation.

Most supercomputers are a hybrid of these kinds of architectures.
### Clusters

Each processor is independent when data some other processor is needed, the other processor must send it. 
- Communication is hand-coded from program to program.

### Shared Memory

Different processors acting on one large bank of memory were all processors see the same data.
- All coordination and communication is done through this shared memory.
- Each core is assigned a thread of execution of a single program that acts on the data.

![[SharedMemory.png]]

### Hybrid Architectures

Multicore nodes linked together with a high-speed interconnect.
- The cores have vector capabilities

![[HybridArch.png]]

#### Hybrid Accelerator Architecture

Nodes also contain one or more accelerators. These are specialized, super-threaded (500 - 2000+) processors.
- CUDA is used to program these devices

HPCs have a number of different components that can vary in the following ways:
## Nodes

- Core: family / type, count, speed
- Memory
- Local Storage: None, SSD, HDD
## Network

- Can have variations in configuration, bandwidth and latency
- There are specialized networks for HPC / datacenters like infiniband, dragonfly, etc.
## Storage and File System

- Almost all HPCs use a parallel file system such as GPFS or Lustre
- HDD vs SDD 
- Backups
## Software

- OS (Linux Distro)
- Scheuduling: Both the scheduler used (eg. Slurm) and the policies around scheuduling jobs within a cluster
- Software and module system
- Administrator tools
## Services

- Water cooling
- Power supply
- Sensors, alarms, security, etc.

Other constraints include budget, use-case, etc.
# Programming Approaches

You should choose your programming approach baes on the type of problem and type of machine:
- Embarrassingly parallel applications: scripting, GNU Parallel
- Shared memory machine: OpenMP, p-threads
### What is the bound of the problem we are trying to solve?

- **Computation bound:** requires task parallelism. Need to focus on parallel processes / threads. These processes have very different computations to do.
- **Data bound**: Requires data parallelism. Bring the computation to the data.
- **I/O bound**: Requires FS parallelism. Reduce IOPs. Reuse memory and keep data in memory.
