$throughput = H = \frac{N}{T}$ where $N$ is number of tasks and $T$ is the total time.

If the tasks are independent and we have $P$ processors, $H$ can be increased by a factor of $P$. 

How a problems scales as processor number increases is **strong scaling**:
- $H \propto P$

For most cases, the processing can be split up but are not completely parallelizable:

**Speedup**: How much faster the problem is solved as processor number increases.
- This measures by the serial time divided by parallel times

$S = \frac{T_{serial}}{T(P)}$
- For embarrassingly parallel applications, $S \propto P$ is a linear speed-up.

### Amdahl's Law

Program speedup is limited by the part that cannot be parallelized.

$S=\frac{1}{f+\frac{1-f}{P}}$
- $f$ is the fraction that must be ran serially and $1- f$ is the fraction that can run in parallel
- $P$ is the number of processors

Gives the upper limit of speedup for a problem of fixed size. 

Approx. parallel part scales linearly with the amount of resources, and the serial part does not increase with respect to the size of the problem.
$$S = s + p \times N$$
- This is called weak scaling, where the scaled speedup is calculated based on the amount of work done for a scaled problem size

- **Strong scaling** is defined as how the solution time varies with the number of processors for a fixed total problem size.
- **Weak scaling** is defined as how the solution time varies with the number of processors for a fixed problem size per processor.

# Profiling

## Tracing

Events happening during code execution are logged.
- Need to know what events you want logged.
- Depending on how it’s done, can slow down code.
- Depending on the tool, may be hard to interpret
## Sampling 

At periodic intervals, the state of the system is logged.
- Detects where program spends its time.
- Statistical; needs enough samples.
- May not detect time in system calls.
## Instrumentation vs Instrumentation-Free

Instrumentation changes the build process such as adding extra code or changing program builds. Instrumentation-Free approaches don't require you to touch the source code but you may need to change how the program is built and run.
